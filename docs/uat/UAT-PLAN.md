# Maglody 新手使用者 UAT 計畫

本輪規格：產品負責人 2026-11-09 session B 指示。保留既有程式與 14 項單元／整合測試，直接在 codex/burn-b 執行。每輪先合併 codex/burn-a；視覺缺失交 A，功能缺失由 B 先重現再修復，逐項本機 commit。禁止 push、部署、tunnel、使用金鑰。

## 執行與驗收

`npm run test:e2e` 使用系統 Chrome（channel: chrome），桌面 1280×800、手機 390×844。Playwright 自行啟動 production preview 4111（strictPort、不重用外部 server），結束自動關閉。音訊使用 Chrome 假麥克風；相片使用 repo icon，API 一律攔截為受控錯誤或受控回應，不呼叫真服務。真麥克風、真人音色、實體手機與真 LLM 不在本輪驗證範圍。

每個案例獨立瀏覽器資料；功能結果必須由 UI 操作與可見結果驗證，storage 僅用來設定明列前置與檢查保存。UAT-03 從空白資料完整走過九檯，不預填專案。其餘下游案例以固定、非機密的完成歌曲作前置。每例在兩 viewport 都執行，總數以「案例 × viewport」計；任一失敗不得宣稱整體通過。R1/R4 的美感與真人相似程度不能只靠 DOM 證明，DOM 加截圖檢視並記錄限制。

每次 run 產生獨立 evidence/<run>/<viewport>/UAT-xx.png（主流程另有各檯截圖），失敗保留 trace。reporter 更新 UAT-RESULTS.md 與 UAT-STATUS.json，並將逐次結果寫至 evidence/<run>/results.json。只有所有案例通過且沒有未結視覺缺失才 ready_for_user_test=true。

# Maglody 使用者驗收計畫

目標：完全新手在瀏覽器裡留下靈感、完成第一版可聽草稿，保有作品所有權與安心試錯的空間。Session A 本機補齊；B 的 UAT 分支若提供 failures.md，仍需接續核對，不能把本報告當作 B 的獨立驗收。

## 執行

```sh
npm run test:e2e
npm run test:logic
```

E2E 自動 build、在 127.0.0.1:4102 啟動 preview、跑完關閉。只用系統 Chrome（channel: chrome），不下載瀏覽器。每案分別跑手機 390×844 和桌面 1280×800；每案有截圖，結果與時間自動寫 UAT-RESULTS.md、UAT-STATUS.json；歷次統計留 UAT-RUNS.json。

`npm run selftest` 使用現有的 4101 preview（另開 `npm run preview -- --host 127.0.0.1 --port 4101 --strictPort`，結束需 Ctrl-C）。UI 專用 suite：`npm run test:ui`，也使用 4101。

通用前置：本機乾淨的 Chrome context、離線 mock 夥伴、沒有 API 金鑰。錄音使用 Chrome 假裝置；拒絕權限/晚到權限/空間不足以明確故障注入，保存讀取真正 IndexedDB，不用假成功。案例內寫明非空專案 fixture 的地方只建立前置，不替代 UAT-40 的真實逐步操作。

## 補充邏輯驗證

`test:logic` 對正式碼執行：取消播放不算自然完成；停止每個鼓與預覽音；取消 callback；靜音不可過錄音；靜音旋律不可過混音；沒構想也能先寫詞；7 小節編曲音訊長度；跨小節延長 MIDI 與段落邊界；離線角色不宣稱產生不存在的 A/B。這些不是實體耳朵的品質判斷。

## 新手探索與範圍

核心驗收綠燈後，另檢查：從空白直接跳混音/總檢討的下一步是否明確；前後切換段落是否中斷；開著聊天捕捉是否保留問題；暗色紙面是否看得清；儲存/媒體失敗後是否保留內容；25 秒錄音上限是否釋放麥克風。新問題追加案例再修。

本輪不部署、不 tunnel、不 push。真實 iOS/Android 麥克風、聽寫、PWA 安裝、真 LLM、主觀音樂品質留待產品負責人實機 UAT，不在本機 Chrome 的 pass 宣告內。
