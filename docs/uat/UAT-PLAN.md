# Maglody 使用者驗收計畫

目標：完全新手在瀏覽器裡留下靈感、完成第一版可聽草稿，保有作品所有權與安心試錯的空間。Session A 本機補齊；B 的 UAT 分支若提供 failures.md，仍需接續核對，不能把本報告當作 B 的獨立驗收。

## 執行

```sh
npm run test:e2e
npm run test:logic
```

E2E 自動 build、在 127.0.0.1:4102 啟動 preview、跑完關閉。只用系統 Chrome（channel: chrome），不下載瀏覽器。每案分別跑手機 390×844 和桌面 1280×800；每案有截圖，結果與時間自動寫 UAT-RESULTS.md、UAT-STATUS.json；歷次統計留 UAT-RUNS.json。

`npm run selftest` 使用現有的 4101 preview（另開 `npm run preview -- --host 127.0.0.1 --port 4101 --strictPort`，結束需 Ctrl-C）。UI 專用 suite：`npm run test:ui`，也使用 4101。

通用前置：本機乾淨的 Chrome context、離線 mock 夥伴、沒有 API 金鑰。錄音使用 Chrome 假裝置；拒絕權限/晚到權限/空間不足以明確故障注入，保存讀取真正 IndexedDB，不用假成功。案例內寫明非空專案 fixture 的地方只建立前置，不替代 UAT-13 的真實逐步操作。

## 使用者旅程案例

| 編號 | 前置 | 使用者步驟 | 預期結果 | 需求 |
|---|---|---|---|---|
| UAT-01 | 首次進入 | 看哼唱檯的紙面、場景與指示 | 紙纖維、水彩、墨線可見；文字可讀、無橫向溢出 | R1 |
| UAT-02 | 空白作品 | 依次進構想、哼唱、歌詞、編曲、錄音 | 角色圖正確載入，五位穿著/髮型/配件與 design.md 一致 | R3 R4 |
| UAT-03 | 哼唱檯 | 點角色，分別向五位提問，再啟用減少動畫 | 每位有回應；作詞人不代寫；待機動畫停止 | R3 R4 |
| UAT-04 | 空白作品 | 九檯巡覽；開選單以 Tab 繞一圈，Escape 關閉 | 每檯最多一主動作，進階收起；焦點留在視窗，關閉回原入口 | R2 A-06 |
| UAT-05 | 空白作品 | 每檯各記一句文字，保存、重整再翻本子 | 始終留原檯，九句均存在 | R5 |
| UAT-06 | 尚未哼唱 | 用示範，先看火花，再點開、再深入 | 動手前無火花；動手後工具箱外一行，原理不自動展開 | R6 |
| UAT-07 | 允許假麥克風 | 記一下→哼→錄音中直接夾進本子→重整 | 視窗關閉且錄音 metadata 與非空 Blob 實際保存 | R5 A-01 |
| UAT-08 | 空白歌詞 | 主歌輸入兩行 | 保持主歌且文字完整，不自動換段 | R2 A-04 |
| UAT-09 | 空白作品 | 直接去旋律點一音試聽，再到總檢討 | 不被和弦前置卡住；已有音符可下載 MIDI | A-07 R2 |
| UAT-10 | 哼唱檯 | 在聊天、選單內開記一下，保存 | 回原視窗且工作未消失 | R5 A-06 |
| UAT-11 | 已開啟 app，再注入 localStorage 滿額 | 選情緒；記文字並保存 | 作品明示未存；捕捉草稿保留，不說已存好 | A-02 R5 |
| UAT-12 | 麥克風拒絕 | 測音量；捕捉哼唱；改寫文字保存 | 回到可重試狀態，文字可存，不假裝錄完 | A-05 R5 |
| UAT-13 | 完全空白 | 示範哼唱→情緒/一句話→主副歌和弦→匯入/改旋律→自己寫主副歌→排骨架與配器→略過麥克風→聽混音/調音量→總檢討→試聽/停止→下載→重整 | 全程不開工具箱即可完成；MIDI 標頭/內容有效、自己的詞和評語保存、無 JS 錯誤 | R1–R6，核心 E2E |
| UAT-14 | 構想有自己的句子 | 存 Demo v1→修改句子→回到這版 | 名稱非空、成功訊息正確、舊文字恢復 | A-02 |
| UAT-15 | 空本子含 seed | 上傳照片與文字→與 seed 拼貼→刪原稿→重整 | 拼貼照片仍能讀出，不因共享 assetId 消失 | R5 A-12 |
| UAT-16 | 模擬權限稍後才同意 | 哼唱請權限→換歌詞檯→權限回來 | 晚到 stream 立刻關閉，沒有偷偷開麥 | A-05 |
| UAT-17 | 空白作品 | 新增 12 歌詞段與長無空格文字；新增 15 編曲段 | 分頁/段落能內部捲動，整頁無水平溢出 | R1 A-09 |
| UAT-18 | 空白歌詞；攔截語音輸出觀察文字 | 寫主歌兩句→聽詞配旋律 | 實際交給語音合成的是主歌，不是固定副歌 | A-11 |
| UAT-19 | 示範哼唱已有大調 | 選憂傷→再聽一次，觀察實際振盪器頻率 | 初聽與重播和弦頻率一致，與和聲設定同調式 | A-13 |
| UAT-20 | 前置有和弦/旋律、主旋律音量 1.2 | 播放→A/B→停→再聽→停→主旋律靜音 | 重播預設自己的混音；靜音不能出現前進成功 | A-14 |
| UAT-22 | 曾注入 IndexedDB 滿額，語音保存失敗 | 改按哼唱，釋出空間後重試並存檔 | 舊語音先救回、哼唱另存；全部 stream 已結束 | A-01 R5 |
| UAT-23 | 哼唱可錄但無法分析音符 | 保存→翻本子→原始哼唱→換檯 | 零音符仍可回播原聲，換檯會停止 | A-01 A-03 R5 |
| UAT-24 | 錄音中裝置提早停止 | 實際觸發 MediaRecorder.stop，再按保存 | 保留提早停止的 Blob，不卡在收好中 | A-01 R5 |
| UAT-25 | 新手在假麥克風錄音後忘記按停 | 等 25 秒，不再操作 | 自動停止全部 track、結束錄音 UI、分析並保留約 25 秒內容 | A-05 R5 |
| UAT-21 | 深色、減少動畫偏好 | 看紙面、人物與工作區 | 暖色夜紙可讀；人物不動；無溢出 | R1 R3 A-09 |

## 補充邏輯驗證

`test:logic` 對正式碼執行：取消播放不算自然完成；停止每個鼓與預覽音；取消 callback；靜音不可過錄音；靜音旋律不可過混音；沒構想也能先寫詞；7 小節編曲音訊長度；跨小節延長 MIDI 與段落邊界；離線角色不宣稱產生不存在的 A/B。這些不是實體耳朵的品質判斷。

## 新手探索與範圍

核心驗收綠燈後，另檢查：從空白直接跳混音/總檢討的下一步是否明確；前後切換段落是否中斷；開著聊天捕捉是否保留問題；暗色紙面是否看得清；儲存/媒體失敗後是否保留內容；25 秒錄音上限是否釋放麥克風。新問題追加案例再修。

本輪不部署、不 tunnel、不 push。真實 iOS/Android 麥克風、聽寫、PWA 安裝、真 LLM、主觀音樂品質留待產品負責人實機 UAT，不在本機 Chrome 的 pass 宣告內。

審查後新增 UAT-22–24：IndexedDB 寫入失敗時的錄音恢復、零音符原聲播放/換檯停止、裝置提早結束。UAT-23 同時檢查主哼唱檯的原始 BufferSource 停止。首次全綠為 24 個案例、雙尺寸 48/48；之後探索追加 UAT-25，最終 25 個案例、雙尺寸 50 次執行。部分案例篩選執行不會把全專案標記 ready。
