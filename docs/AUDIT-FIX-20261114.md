## 各項紀錄

### M-01｜Cloud Run 部署崩潰（完成）

- **做法**：選報告的 (a)。`reply.ts`、`request.ts`、`prompts.ts` 搬到 `server/shared/`，新增 `personas.ts`、`limits.ts`、`rate-limit.ts` 也放這裡。為什麼不是 `shared/`：文件教的 `gcloud run deploy --source server` 只會上傳 `server/`，放在外面就得換成根目錄 Dockerfile 與新的部署指令，這裡沒辦法驗證。這樣既有指令照舊能用，`server/` 也不再匯入 `src/`（順便滿足 M-20 的第三條驗收）。
- **容易踩的坑**：後端在容器裡是純 Node 直接跑 TypeScript，相對 import 一定要寫 `.ts`；測試載入器會幫忙補副檔名，單元測試會過、容器卻會崩。所以 `tsconfig.json` 開 `allowImportingTsExtensions`，並加了 `scripts/tests/server-imports.test.mjs`（不准引用 `server/` 外面、相對 import 要有 `.ts`）。
- **驗證**：新增 `npm run test:deploy`（`scripts/deploy-smoke.mjs`）。照 `server/Dockerfile` 的 `COPY` 範圍把後端複製到空暫存資料夾，用純 `node server/index.ts`（沒有載入器、沒有 `src/`）啟動，打 `/api/health`。**修之前在 main 上實跑會 FAIL**：`ERR_MODULE_NOT_FOUND …/src/lib/request.ts`；修完 PASS。故意把 `gcp.ts` 的 import 改回 `../../src/…`，單元測試與煙霧測試都會紅，再還原。
- **沒做到的**：這台機器沒有 Docker，**沒有真的建映像**，煙霧測試驗的是「複製範圍＋啟動指令」。驗收標準裡「在 CI 裡跑」那一條要等 M-19 的 workflow。

### M-02｜`/api/master` 沒驗證、沒限流（完成）

- **請求格式改了**：只收 `step`、`persona`（代號 `producer`…）、`songContext`、`event`、`question`、`history`。`system`／`messages` 出現就回 400，不收前端自己寫的角色文字。system prompt 與夥伴設定、`buildUserTurn` 都在後端組。
- **限流**：每個來源每分鐘 20 次（`RATE_PER_MINUTE`）、全服務每日 3000 次（`RATE_PER_DAY`），超過回 429 並帶 `Retry-After`。來源取自 socket；放在代理後面要設 `TRUST_PROXY_HOPS=1`，取 `X-Forwarded-For` 最後一段（最左邊可以被偽造，不信）。計數放在記憶體，重啟或多開就各算各的，文件已寫明，預算上限仍是最後一道防線。
- **輸入上限**：body 200 KB → 80 KB。依最長的正常請求估（歌曲摘要 8,000 字＋8 則歷史各 1,600 字，約 62 KB），前端送出前先裁到同一組上限（`server/shared/limits.ts`），不然長歌會無聲退回離線夥伴。測試有一筆「全部寫滿」的請求要求仍回 200。
- **驗證**：`unit` 新增並通過——帶 `system`／`messages` 回 400 且不會呼叫模型、送到模型的 system 永遠是後端那份、夥伴文字由後端查表、第 N+1 次回 429（含 `Retry-After`、別的來源不受影響、過一分鐘恢復）、每日總量、偽造 `X-Forwarded-For` 被忽略、超過上限回 413、前端送出的 body 沒有 `system` 且歷史有被裁短。原有的 400／413／415／403／502 斷言都留著，只是 body 換成新格式。
- **文件**：README 加三個環境變數；`cloud-setup.md` 把「預算上限是最後一道防線」改成「限流＋預算上限」，保留 `--allow-unauthenticated`（瀏覽器沒辦法帶 Google 憑證，拿掉就叫不動）並寫明原因，部署指令加 `TRUST_PROXY_HOPS=1`；順手把文件裡過期的 `feature/music-lab` 分支名改成 `main`。
