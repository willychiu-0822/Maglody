# Maglody × MIDI 鍵盤 × Ableton Live 設計

> 2026-11-13 晚，第一版。這個環境沒有實體鍵盤也沒有 Ableton：凡標「未確認」「WIP」的項目都還沒在真機上跑過，要 Willy 在自己的電腦上確認，本文不宣稱任何實機項目已通過。

## 1. 目標與範圍

Willy 買了 Arturia MiniLab 鍵盤（他稱「MiniLab 37」，屬 MiniLab 3 家族，型號見 4.2）和 Ableton Live Lite，想一邊玩 Maglody 一邊把這兩樣學起來。做法是讓現有角色順手帶：作曲家帶你用實體琴鍵彈旋律、和弦、動機；編曲家帶你用打擊墊、旋鈕，最後把歌匯出成 .mid 拖進 Ableton。範圍只含瀏覽器 Web MIDI 輸入、標準 MIDI 檔匯出與引導文案；不做外掛、不寫 Ableton 控制腳本、不碰 sysex。沒有鍵盤的人玩起來要和現在完全一樣。

## 2. 玩家旅程

每一頁只有一個主要按鈕（實心），其餘一律次要樣式。瀏覽器在授權前看不到任何 MIDI 裝置，所以「角色發現鍵盤」第一次一定要玩家先點一下；授權過之後才是插上就認得。

| 步驟 | 畫面上看到什麼 | 誰說話 | 唯一的主要按鈕 |
| --- | --- | --- | --- |
| 1 插上鍵盤 | 旋律頁角落一顆次要小鈕「接上鍵盤」（只在瀏覽器支援時出現）。點下去跳出瀏覽器的 MIDI 授權視窗 | 沒有人說話，不打斷 | 旋律頁原本的「▶ 循環聽」不變 |
| 2 角色發現鍵盤 | 作曲家旁出現一行提示「鍵盤已接上」＋裝置名稱；螢幕鍵盤照樣留著 | 作曲家：「欸，你接了鍵盤。彈一個音給我聽。」 | 「▶ 循環聽」不變（提示不帶按鈕，彈一個音就收起來） |
| 3 作曲家關卡改用琴鍵 | 旋律頁：彈一個音，目前那一格就填上並往前一格；和聲頁：按住和弦，畫面顯示聽到的音與級數；哼唱頁：彈回剛哼的動機，音高線疊在哼唱線上 | 作曲家，先說聽到的音 | 各頁原本那一顆：旋律頁「▶ 循環聽」（寫完變「旋律有了，去… →」）；和聲、哼唱沿用現有的主要按鈕 |
| 4 編曲家帶你用墊子與旋鈕 | 編曲頁：八顆墊子對應畫面上八個格子，敲了會亮；混音頁：推桿對到各軌音量，畫面的推桿跟著動 | 編曲家：「鍵盤上那八顆墊子，借我用一下。」 | 編曲頁「▶ 試聽…」（排完變「編好了，去… →」）、混音頁「▶ 播放副歌」；「學習對應」放在設定裡，次要樣式 |
| 5 匯出拖進 Ableton | 總檢討頁的 Ableton 引導卡：三步驟小圖（存檔 → 拖進 Session View → 換音色）＋這首歌的速度數字 | 編曲家：「四軌都包好了，拖進 Ableton 聽聽。」 | 總檢討頁仍是「▶ 從頭聽我的歌」；卡片上的「下載 MIDI，帶進 Ableton」是次要樣式（引導若做成彈窗，彈窗裡唯一的主要按鈕才是「下載 MIDI」） |

## 3. 角色台詞口吻

依 `docs/VOICE-GUIDE.md`：夥伴口氣、一兩句、不說教、不講「正確」。作曲家先說聽到的音；編曲家給一個試法。

作曲家

- 接上：「欸，你接了鍵盤。彈一個音給我聽。」
- 第一次彈：「聽到了，是 Mi。往上再找一個音看看？」
- 彈錯也沒關係：「這個音在調外面，可是有點意思。要留著，還是換旁邊那顆？」
- 和弦：「Do、Mi、Sol，是這首歌的一級。換一個手型試試。」
- 彈回動機：「剛剛哼的那句，用手找找看。差一點也沒關係。」
- 拔掉：「鍵盤先休息了。畫面上的琴鍵一樣能彈。」
- 不支援的瀏覽器：「這個瀏覽器聽不到鍵盤。用 Chrome 開就接得上，現在先點畫面上的也行。」
- 進 Ableton 之後：「先挑一個你喜歡的鋼琴聲，把那句再彈一次。」

編曲家

- 接上：「鍵盤上那八顆墊子，借我用一下。」
- 第一次敲：「這顆是大鼓。敲旁邊那顆，聽聽差在哪。」
- 敲歪也沒關係：「拍子飄了一點，沒差。再來四拍。」
- 旋鈕：「轉第一顆，鼓會退到後面。聽聽這兩種。」
- 學習對應：「這顆我還不認得。按一下，我記起來。」
- 拔掉：「墊子斷線了。畫面上的格子一樣能點。」
- 不支援的瀏覽器：「這裡接不到墊子。換 Chrome 再來，或先用點的。」
- 匯出：「旋律、和弦、貝斯、鼓，四軌都包好了。存下來，拖進 Ableton。」
- 進 Ableton 之後：「先幫鼓那軌換一組鼓聲。只換一樣，聽聽差別。」

## 4. 技術作法

### 4.1 Web MIDI 輸入（`src/lib/midiInput.ts`，實作中）

- 進入點：`navigator.requestMIDIAccess({ sysex: false })`。不要 sysex，授權門檻最低。
- 瀏覽器支援（S8、S9）：Chrome 43+、Edge 79+ 可用；Firefox 108+ 有，但要先裝「網站權限附加元件」才放行；Safari（macOS 與 iOS）不支援，iOS 上其他瀏覽器同樣沒有。
- Chrome 124 起，不含 sysex 的 `requestMIDIAccess()` 也會跳授權視窗（S8）。
- 需要安全環境（HTTPS 或 `localhost`）（S9）；用區網 IP 的 http 開手機測試時 API 不存在，會直接走退路。
- 授權一定由使用者手勢觸發（點「接上鍵盤」）。已授權過的可先用 `navigator.permissions.query({ name: 'midi' })` 判斷：`granted` 進頁就自動接；`prompt` 等玩家點；`denied` 走退路。（permissions 查詢的瀏覽器支援度：未確認，查不到就當 `prompt`。）
- 熱插拔：監聽 `MIDIAccess.onstatechange`，`port.type === 'input'` 且 `state` 變 `connected` 就掛上 `onmidimessage`，變 `disconnected` 就放掉所有還按著的音，避免卡音。
- 每個 `MIDIMessageEvent.data` 是一則完整訊息（沒有 running status），依第一個位元組判斷：

| 訊息 | 狀態位元組 | 資料 1 | 資料 2 | Maglody 怎麼用 |
| --- | --- | --- | --- | --- |
| Note Off | `0x8n` | 音符 0–127 | 放開力度 | 放音 |
| Note On | `0x9n` | 音符 0–127 | 力度 1–127；**力度 0 視為 Note Off** | 發聲；力度只影響試聽音量 |
| Control Change | `0xBn` | 控制器編號 | 值 0–127 | 旋鈕、推桿、Mod |
| Pitch Bend | `0xEn` | LSB | MSB（14 位元，中點 8192） | 第一階段忽略 |
| Aftertouch | `0xAn`／`0xDn` | — | — | 忽略 |
| 即時訊息 | `0xF8`、`0xFE` 等 | — | — | 忽略 |

`n` 是頻道減一（頻道 1 → `0`，頻道 10 → `9`）。音符 60 = 中央 C。

- 琴鍵與打擊墊的分辨：先看 MIDI learn 的結果；沒學過就用預設規則「頻道 10 且音符 36–51 → 墊子，其餘 → 琴鍵」。
- 旋鈕：把 CC 值 0–127 正規化成 0–1 再交給頁面。若旋鈕送的是相對值（只在 64 上下跳），learn 時記成 `relative` 改用累加。

### 4.2 MiniLab 預設對應＋MIDI learn

型號：「MiniLab 37」是正式產品，Arturia 於 2026 年 6 月推出，是 MiniLab 3 的 37 鍵版（比 25 鍵多 12 個薄型鍵），附 Ableton Live Lite 與 MIDI Control Center（來源 S3–S5）。控制數量：Synth Anatomy 寫 8 墊、8 旋鈕、4 推桿（與 MiniLab 3 相同）；另有一家通路寫 16 墊、9 推桿（S6）——來源不一致，**未確認**，以 Willy 手上那台為準。報導提到「新配置」，所以 MiniLab 37 的預設 MIDI 對應是否沿用 MiniLab 3：**未確認**。下表是 MiniLab 3 的資料。

| 控制 | 預設送出 | 狀態 |
| --- | --- | --- |
| 琴鍵 | Note On/Off，頻道 1 | 未確認 |
| 打擊墊 A 組 1–8 | 頻道 10，音符 36–43 | 未確認 |
| 打擊墊 B 組 1–8 | 頻道 10，音符 44–51 | 未確認 |
| 旋鈕 1–8 | CC 74、71、76、77、93、18、19、16 | 未確認 |
| 推桿 1–4 | CC 82、83、85、17 | 未確認 |
| Mod 觸控條 | CC 1 | 未確認 |
| Pitch 觸控條 | Pitch Bend | 未確認 |

因為表上都還沒經過實機確認，而且 MiniLab 的每個程式（Arturia／DAW／User）對應都能改，**App 不把這張表寫死**，只當「沒學過時的第一猜」，並提供 MIDI learn：在設定裡按一下墊子／轉一下旋鈕來學習對應。

```ts
type MidiBinding =
  | { kind: 'note'; channel: number; note: number }
  | { kind: 'cc'; channel: number; controller: number; mode: 'absolute' | 'relative' }

interface MidiMapping {
  version: 1
  deviceName: string            // MIDIInput.name
  pads: (MidiBinding | null)[]   // 8 格
  knobs: (MidiBinding | null)[]  // 8 格
  faders: (MidiBinding | null)[] // 4 格
  learnedAt: string             // ISO 時間
}
```

- 存放：`localStorage['maglody.midiMapping.v1']`，以裝置名稱為鍵；讀不到或格式不對就退回預設猜測。
- 流程：設定 →「學習對應」→ 畫面亮起第一格 → 玩家按一下實體墊子（或轉一下旋鈕）→ 收到的第一則 Note On／CC 記進這一格 → 自動跳下一格。可以「跳過這顆」，可以「回到預設」。琴鍵不用學。

### 4.3 第二階段（未做）：Web MIDI 輸出到虛擬埠，即時送進 Ableton

- macOS：「音訊 MIDI 設定」→ MIDI 工作室 → IAC 驅動程式 → 勾「裝置已上線」。Windows：裝 loopMIDI 建一個虛擬埠。Ableton 的 MIDI 設定把該埠的 Track 輸入打開。
- App 用 `MIDIOutput.send()` 把玩家彈的音或播放中的歌送到該埠。
- 風險：延遲（瀏覽器 → 虛擬埠 → Live 多一段）；迴授（Live 又把音送回同一個虛擬埠，App 若同時聽那個埠會無限迴圈 → App 的輸入清單要排除自己選的輸出埠）；重複發聲（Live 同時直接收鍵盤、又收 App 轉送的）；Windows 上瀏覽器與 Live 能否同時開同一支鍵盤：未確認。全部要實機驗證。

| 0 | Tempo | — | tempo meta `FF 51 03`（每四分音符微秒數）、拍號 |
| 1 | 主旋律 Melody | 1 | 旋律頁的音 |

## 5. 退路

- 沒有鍵盤：什麼都不出現，螢幕鍵盤／琴格照常。
- 瀏覽器不支援（Safari、iOS 上所有瀏覽器等）：不顯示「接上鍵盤」；只在玩家第一次進旋律頁時由作曲家說一次，之後不再出現（記在 localStorage）。
- 授權被拒：提示一次「畫面上的琴鍵一樣能彈」，不跳視窗、不重複要求；設定裡留「再試一次」。
- 中途拔掉：放掉所有按著的音，提示一行，三秒後自己收起來。
- 任何情況下 MIDI 都不是過關條件；提示不蓋住主要按鈕。
