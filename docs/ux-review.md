# UX 自測紀錄：完全新手、手機直向

## 第 3 輪（極簡改版）：「一屏一個主動作」

**觸發**：使用者回饋「介面太複雜、每頁沒有主次、按鈕太多、多重點，看了就不想用」。

**做法**：先砍，再美化。
- 拿掉旅程節點列、階段列、四張起點卡、常駐大師列、底部播放鍵、每檯的完成條件清單、上一章／跳過／完成三顆按鈕。
- 每一檯改成：夥伴頭像（一句登場或旁白）→ 一句大字 → 工作區 → 1 個主動作 → 最多 1 個文字連結 → 收起的「＋ 工具箱」。
- 前進按鈕只在做完時出現，並取代主動作。
- 常駐元素只剩兩個：左上「工作室 ▾」選單、右上「✎ 記一下」貼紙。
- 工作室夥伴（製作人／作曲家／作詞人／編曲／錄音師）在對的檯位悄悄登場；點頭像就能聊，在對話視窗裡可以換成任何一位。

**量測**（Playwright 模擬 iPhone 13，走完哼唱 → 構想 → 和聲 → 旋律 → 歌詞 → 編曲 → 記靈感 → 從「負罪前行」開始 → 跟作詞人聊）：

| 畫面 | 主動作數 | 可見的次要動作 |
|---|---|---|
| 哼唱 首屏 | 1（● 哼一段） | 沒有麥克風？聽示範 |
| 哼唱 錄音中 | 1（■ 哼完了） | — |
| 哼唱 完成 | 1（用這段繼續：構想 →） | ▶ 聽聽整理後的音 |
| 構想 首屏 | 0（工作區是情緒紙片） | — |
| 構想 完成 | 1（帶著這句話，去和聲 →） | ▶ 再聽一次這個感覺 |
| 和聲 首屏 | 0（工作區是和弦） | — |
| 和聲 主歌滿 | 1（▶ 循環聽主歌） | 換副歌 → |
| 和聲 完成 | 1（地板鋪好了，去旋律 →） | ▶ 循環聽副歌 |
| 旋律 首屏 | 1（用我的哼唱當草稿） | — |
| 旋律 完成 | 1（旋律有了，去歌詞 →） | ▶ 循環聽 |
| 歌詞 完成 | 1（詞有了，去編曲 →） | ▶ 聽詞配旋律 |
| 編曲 首屏 | 1（排一個常見的骨架） | — |
| 編曲 完成 | 1（編好了，去錄音準備 →） | ▶ 試聽副歌 |

所有畫面主動作 ≤ 1、次要 ≤ 1、0 個水平溢出、0 個 JS 錯誤。另外可見的只有：夥伴頭像、主歌／副歌兩個安靜分頁、手機旋律格的小節分頁。

### 第 3 輪複測（斷言式腳本）

腳本：`scripts/mobile-selftest.cjs`（`npm run build && npx vite preview --port 4173`，另開一個終端機執行 `npm run selftest`）。這次不靠肉眼看截圖，每一項都是程式斷言。

**第一次跑：50 項中 2 項 FAIL**，兩項都是測試腳本的錯，不是產品的錯：
- 靈感貼紙「誤點」：原本用 `.primary-action` 取第一個，點到的是背後那一檯的主動作。改成只點對話框內的 `.inspo-sheet .primary-action`。
- 作詞人不代寫：原本抓的是第 3 則旁白，不是「幫我寫一句」的回答。改成抓那則提問之後的第一則回答。

**跑測試時另外發現的產品問題（已修）**
| # | 問題 | 修正 |
|---|---|---|
| R7 | 本子展開某一則靈感後，有 1 個主動作，卻同時列出 2–4 個連結 | 只留主動作＋「其他用法…」；播放鍵等展開後才出現 |
| R8 | 混音預設把貝斯放偏右，會亮紅燈；但聲像控制在工具箱裡，新手不打開工具箱就過不去 | 預設貝斯置中；只留「主旋律太小聲」，用主畫面推桿就能修好。測試改成不打開工具箱也要能過 |
| R9 | 假麥克風的音量測到 0 dB（太滿）→ 不給前進 | 這是正確行為：大字提示「退後一點再試」，次要連結「先跳過」可以繼續。已加入斷言 |

**最終結果：50 / 50 PASS**，涵蓋：
- 9 檯 × 各狀態都 ≤ 1 主動作、≤ 1 次要動作，沒有水平溢出（共 25 個畫面）。
- 主流程從哼唱（假麥克風）走到總檢討，全程沒有打開任何工具箱。
- 角色依檯位登場：構想＝製作人、和聲＝作曲家、歌詞＝作詞人、錄音＝錄音師。
- 在構想檯分別跟 5 位夥伴聊，回答者都正確；作詞人拒絕代寫整句。
- 同一則靈感同時有文字、語音、哼唱、照片（錄音中加入照片）；存完留在原地。
- 本子裡有「負罪前行」；從它開始會進入構想，記憶點＝負罪前行。
- 拼貼：勾兩則會出現拼貼選項，並能合成新靈感。
- 工作室選單列出 9 檯，可以直接跳到任一檯。
- 沒有 JS 錯誤。

**這份測試沒有涵蓋、不能宣稱已過的**
- 實體手機（iOS Safari、Android Chrome）：權限彈窗、靜音鍵、語音聽寫的實際辨識、觸控手感、字型。
- 真實的 OpenAI、Gemini、Vertex 呼叫：只在本機假端點驗過格式；LLM 模式下角色語氣是否到位、是否守住不代寫，都還沒驗證。目前的角色對話是離線 mock，內容依問題類型回答，五位的語氣差異很小。
- 構想、和聲、歌詞首屏沒有主動作（工作區本身就是動作），新手會不會不知道要點哪裡（R6），需要實機觀察。
- 「主旋律推到最清楚」的混音判斷是規則式的，不代表真的好聽。

## 第 1–2 輪

## 方法

- **裝置**：Playwright 模擬 iPhone 13（390×844、觸控、`deviceScaleFactor` 3），Chromium 以假麥克風裝置提供音訊，並允許麥克風權限。
- **環境**：`npm run build` 後用 `vite preview` 測正式版。
- **自動檢查**：每一頁檢查水平溢出、小於 36px 的觸控目標、小於 12px 的文字、JS 錯誤。
- **人工檢查**：每一步都截圖，用「第一次打開、不懂樂理」的眼光檢查：看不看得出下一步該按什麼、文字讀不讀得動、有沒有被蓋住的東西、會不會卡住。
- **測試情境**：
  - A 主流程：哼唱（假麥克風＋示範哼唱）→ 構想 → 和聲（排 8 格＋聽辨 4 題）→ 旋律（匯入哼唱）→ 歌詞 → 編曲 → 隨手記 → 翻本子 → 從「負罪前行」開始 → 問大師「換一個更哀傷的走向」
  - B 突發靈感：一進來就記 → 同一則裡打字＋說話＋（錄音中）加照片＋哼一段 → 存檔 → 從 seed 開始 → 重新整理後資料仍在
  - C 工作室：三階段、四種起點、勾 3 則拼成一段歌詞、存成 Demo v1
  - D 後端：OpenAI Chat／OpenAI Responses／Gemini API／Vertex AI 四條路徑，用本機假端點驗證請求格式、授權標頭與輸出淨化；缺金鑰時的錯誤訊息
